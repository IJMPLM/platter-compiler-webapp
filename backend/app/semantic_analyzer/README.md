# Semantic Analyzer - Multi-Pass Architecture

This directory contains the semantic analysis phase of the Platter compiler, implemented as a modular multi-pass system.

## Overview

The semantic analyzer takes the Abstract Syntax Tree (AST) generated by the parser and performs deep semantic validation across 5 separate passes. This clean separation ensures:

- **Modularity**: Each pass has a single, well-defined responsibility
- **Maintainability**: Easy to add new passes or modify existing ones
- **Debuggability**: Clear progression through analysis stages
- **Extensibility**: New validation rules can be added without affecting existing passes

## Architecture

### Main Orchestrator: `semantic_analyzer.py`

The `SemanticAnalyzer` class coordinates all passes in sequence:

```python
analyzer = SemanticAnalyzer(ast)
success = analyzer.analyze()
```

The analyzer executes 5 passes in order, stopping if any pass fails.

## The 5 Passes

### Pass 1: Symbol Table Builder ✓ IMPLEMENTED
**File**: `symbol_table_builder.py`

Builds two separate symbol tables by traversing the AST:

#### Ingredient Table (Variables)
Tracks all variable declarations with complete metadata:
- **name**: Variable identifier
- **type**: Data type (piece, sip, flag, chars, or table name)
- **line, col**: Source location for error reporting
- **scope**: Scope name (global, function name, etc.)
- **scope_level**: Numeric scope depth (0 = global)
- **is_array**: Whether it's an array declaration
- **dimensions**: Array dimensions (if applicable)
- **initialized**: Has initial value
- **init_value**: The initialization value
- **is_parameter**: Function parameter flag
- **is_global**: Global scope flag
- **used**: Tracked in later passes
- **assigned**: Tracked in later passes

#### Recipe Table (Functions)
Tracks all function/recipe declarations:
- **name**: Recipe identifier
- **line, col**: Source location
- **return_type**: Return type (None for void)
- **parameters**: List of parameter dictionaries
- **parameter_count**: Number of parameters
- **is_builtin**: Built-in function flag
- **is_main**: Whether it's the start() function
- **called**: Tracked in later passes
- **recursive**: Tracked in later passes
- **body_analyzed**: Analysis status flag

**Validations**:
- ✓ No duplicate variable declarations in same scope
- ✓ No duplicate function declarations
- ✓ Proper scope management (enter/exit)
- ✓ Source location tracking for all symbols

## Usage

### Basic Usage

```python
from app.lexer.lexer import Lexer
from app.parser.parser import Parser
from app.semantic_analyzer.semantic_analyzer import SemanticAnalyzer

# 1. Lex
lexer = Lexer(source_code)
tokens = lexer.tokenize()

# 2. Parse
parser = Parser(tokens)
ast = parser.parse()

# 3. Semantic Analysis
analyzer = SemanticAnalyzer(ast)
success = analyzer.analyze()

if success:
    # Access symbol tables
    ingredient_table = analyzer.get_ingredient_table()
    recipe_table = analyzer.get_recipe_table()
    
    # Use for code generation or further analysis
else:
    # Handle errors
    errors = analyzer.get_errors()
    for error in errors:
        print(f"Error: {error}")
```

### Symbol Table Access

```python
# Get ingredient table
ingredients = analyzer.get_ingredient_table()

# Look up a variable
symbol = ingredients.lookup('temperature')
if symbol:
    print(f"Variable: {symbol['name']}")
    print(f"Type: {symbol['type']}")
    print(f"Scope: {symbol['scope']}")
    print(f"Initialized: {symbol['initialized']}")

# Get all ingredients
all_ingredients = ingredients.get_all_ingredients()
for name, declarations in all_ingredients.items():
    for decl in declarations:
        print(f"{name}: {decl['type']} (line {decl['line']})")
```

```python
# Get recipe table
recipes = analyzer.get_recipe_table()

# Look up a function
recipe = recipes.lookup('calculateTotal')
if recipe:
    print(f"Function: {recipe['name']}")
    print(f"Return type: {recipe['return_type']}")
    print(f"Parameters: {len(recipe['parameters'])}")
    for param in recipe['parameters']:
        print(f"  - {param['name']}: {param['type']}")

# Get all recipes
all_recipes = recipes.get_all_recipes()
for name, recipe in all_recipes.items():
    print(f"{name}({recipe['parameter_count']} params) -> {recipe['return_type']}")
```

## Error Handling

The semantic analyzer collects errors without stopping immediately (where possible):

```python
if not analyzer.analyze():
    print("Semantic analysis failed:")
    for error in analyzer.get_errors():
        print(f"  ERROR: {error}")
    for warning in analyzer.get_warnings():
        print(f"  WARNING: {warning}")
```

## Symbol Table Structure

### Scope Management

The IngredientTable maintains a scope stack:

```python
# Global scope (level 0)
ingredients.enter_scope('myFunction')  # Level 1
ingredients.declare('local_var', 'piece', line, col)
ingredients.enter_scope('nested_block')  # Level 2
# ...
ingredients.exit_scope()  # Back to level 1
ingredients.exit_scope()  # Back to level 0 (global)
```

### Lookup Behavior

Variable lookup searches from innermost to outermost scope:

```python
# If 'x' is declared in global and local scope,
# lookup returns the local one (shadowing)
symbol = ingredients.lookup('x')
# Returns innermost declaration

# Lookup only in current scope
symbol = ingredients.lookup_current_scope('x')
# Returns None if not in current scope
```

## Implementation Notes

### Key Design Decisions

1. **Separate Tables**: Ingredients and recipes are kept in separate tables rather than one unified symbol table. This simplifies lookups and prevents name collisions between variables and functions.

2. **Scope Stack**: Scopes are managed with a stack, allowing proper variable shadowing and scope-based lookup.

3. **Complete Metadata**: Each symbol stores comprehensive information including source location, initialization status, and usage tracking for later passes.

4. **Early Error Detection**: Pass 1 detects duplicate declarations immediately, preventing cascading errors in later passes.

5. **Token Preservation**: All symbol information is extracted from tokens stored in the AST, maintaining complete traceability to source code.

### AST Traversal

The symbol table builder uses the visitor pattern to traverse the AST:

- `visit_program()`: Entry point
- `visit_global_decl()`: Global declarations
- `visit_decl_data_type()`: Type declarations
- `visit_recipe_decl()`: Function declarations
- `visit_ingredient_id()`: Variable identifiers
- `visit_ingredient_id_tail()`: Comma-separated declarations

Each visitor method extracts relevant information from AST nodes and calls appropriate symbol table methods.
